Timing closure on the RISC-V core

Final numbers from my RTL-to-GDSII run at 400 MHz. Slack is the margin on a timing check: positive means it passes, negative means a violation.

Single-cycle RISC-V core, OpenROAD (ORFS), Nangate45All checks met
CheckResultStatusWhat it tells you
Clock period2.5 ns (400 MHz)TargetThe time each cycle lasts. Every path has to finish inside it.
Setup slack+0.21 nsMetData arrived 0.21 ns before the deadline set by the next clock edge.
Hold slack+0.11 nsMetData stayed stable 0.11 ns longer than the minimum after the clock edge.
Removal slack+0.12 nsMetHold's counterpart for releasing reset: it came 0.12 ns later than the minimum.
Area~13,800 µm²ReportedPlaced and routed size, with 1,024 flops.

I swept the clock from 10 ns down to 2 ns and fitted slack ≈ 0.6×T − 1.35 ns. That puts reset removal as the next limit, at about 1.9 ns.

Physical design and verification

Single-cycle RISC-V core: RTL-to-GDSII and verification

  • Verilog
  • Yosys
  • OpenROAD (ORFS)
  • Nangate45
  • Docker
  • Designed a single-cycle core (12 instructions, 32x32 register file, 1,024 flops) and took it through RTL-to-GDSII.
  • Debugged a hollow first run: a constant instruction let synthesis prune the register file down to 30 flops. I confirmed it from a LOGIC0-driven net, then added memory ports and a top-level wrapper to get a real 1,024-flop baseline.
  • Verified with a 22-check directed test, a monitor and scoreboard (135 checks), and constrained-random tests (20 seeds, about 7,900 checks, 0 mismatches). Mutation tests confirmed the checkers catch injected bugs.

NOMA underwater acoustic communication on FPGA

  • Final year project, team of 3
  • MATLAB
  • Verilog
  • Quartus Prime
  • DE1-SoC (Cyclone V)
